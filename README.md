# iProxypac

`proxy.pac` を管理・生成・テストするための単一HTMLツールです。すべての機能が `iProxypac.html` 1ファイルに収まっており、外部API・CDN・外部ライブラリには依存しません。閉域環境にファイルを1つコピーするだけで利用できます。

現在のバージョン: **v0.1.3**（変更履歴は [CHANGELOG.md](CHANGELOG.md)）

## 目的

閉域環境から国提供システム等のパブリックサイトへアクセスするために `proxy.pac` を運用していると、次のような課題が発生しがちです。

- PACを手書きすることによる構文ミス
- 新しいルールを追加した際の、既存システムへの巻き添え（意図しないルールの上書き・シャドーイング）
- どのURLがどのルールに該当しているのかが分かりにくい
- PACを安全にデバッグできる環境がない

iProxypac は、対象システムを**構造化データ（システム台帳）として管理**し、その情報から `proxy.pac` を**自動生成**し、**URL単体テスト**と**全件回帰テスト**を行えるようにすることで、これらの課題に対応します。

## 入手と起動

`iProxypac.html` をダウンロードし、ブラウザで開くだけで動作します。インストールもサーバも不要です。

リポジトリには、このファイルを GitHub Pages へ公開するワークフロー（`.github/workflows/pages.yml`）も含まれています。公開ページも同じ単一ファイルであり、入力した内容がブラウザの外へ送信されることはありません。

## 主な機能

- **システム管理**: システム名・備考・優先順位・接続方法・このシステムと判定する条件（複数）・回帰テストURL（複数）・有効/無効を一覧管理
- **判定条件**: 「ホスト名が完全一致」「ワイルドカードで一致」「ドメイン配下に一致」「IPアドレスが完全一致」という意味の分かる名称で選択（内部的には host完全一致 / `shExpMatch` / `dnsDomainIs` / IPアドレス完全一致に対応）。`isPlainHostName` は共通ルールとして別枠で管理
- **アクセス経路管理**: `DIRECT` / `PROXY host:port` などをマスターとして一元管理し、システム側では選択するだけ。`HTTPS` / `SOCKS4` / `SOCKS5` / `SOCKS` キーワードにも対応
- **優先順位管理**: 一覧から並び替え可能。PAC生成時も必ずこの順序を使用（先に一致した条件が優先）
- **PAC自動生成**: 人間が読みやすい整形済みコードを生成。同じ設定からは常に同じPACが生成される
- **入力検証**: システム名未入力、条件未入力、不正なIP、不正なポート、重複条件、経路の競合、無効な経路参照などをエラー/警告に分けて検出
- **PAC構文検証**: 生成したコードを実際に `Function` として構築し、`FindProxyForURL` が定義できること・構文エラーがないことを確認
- **URL単体テスト**: Chromium系ブラウザがPACへ渡すURL（path/queryが除去される挙動）を模したうえで、生成PACを実際に実行して判定結果を表示
- **全件回帰テスト**: 各システムの登録済みテストURLと、システムに属さない「ガードテスト（対象外URLがDIRECTのままであることの確認等）」をまとめて実行し、PASS/FAILを集計
- **重複・競合検出**: 完全一致条件の重複、異なる経路への割り当て、広いワイルドカードによる狭い条件のシャドーイングなどをヒューリスティックに警告
- **設定変更の追随**: 設定を1箇所でも変更すると、生成済みPAC・構文検証結果・テスト結果を自動的に無効化し、古いPACを誤って使うことを防止
- **JSON保存・復元**: すべての設定をJSONとしてエクスポート/インポート可能（`formatVersion` により将来の互換性に配慮）
- **proxy.pac出力**: 検証済みのPACをファイルとしてダウンロード

## 基本的な利用手順

1. **アクセス経路を登録する**（「アクセス経路」タブ）
   `DIRECT` や `PROXY 192.0.2.10:8080` など、実際にPACが返す値をマスターとして登録します。ここで付けた「表示名」（例: 国システム用プロキシ）が、システム登録画面では「接続方法」の選択肢として表示されます。既定経路（最終的にどの条件にも一致しなかった場合の経路）もここで設定します。
2. **システムを登録する**（「システム」タブ）
   「+ システム追加」を開くと、以下の流れで1つのシステムを登録できます。
   1. システム名を登録する
   2. このシステムと判定する条件を登録する（「ホスト名が完全一致」「ワイルドカードで一致」など、意味の分かる名称から選択し、値を入力します。PAC関数名を知らなくても設定できます）
   3. 条件に一致した場合の接続方法を選択する（選んだ経路の実際のPAC値や、`DIRECT` の意味がその場で表示されます）
   4. 必要に応じて回帰テストURLを登録する
   ダイアログ内には「この設定の意味」として、登録内容を自然文でまとめたプレビューが表示され、条件や接続方法を変更すると即座に更新されます。
3. **URL単体テストを行う**（「テスト」タブ）
   実際に判定したいURLを入力し「判定」を押すと、PAC評価用URL・host・判定結果・該当システム・該当条件が表示されます。
4. **全件回帰テストを行う**
   「全件回帰テスト実行」で、登録済みの全テストURLと共通（ガード）テストをまとめて実行し、PASS/FAILを確認します。
5. **PACを生成する**（「PAC」タブ）
   「検証してPACを生成」を押すと、入力検証・PAC構文検証・回帰テストが一括で行われ、生成されたコードがプレビューされます。エラーがある場合は生成されません。
6. **`proxy.pac` を出力する**
   内容を確認のうえ「proxy.pac をダウンロード」でファイルを出力します。回帰テストにFAILが残っている場合は警告が表示されますが、出力自体は可能です。本番投入前に必ず内容を確認してください。

## データの保存とバックアップ

設定はブラウザの `localStorage` へ自動保存されますが、**これはバックアップではありません。** ブラウザのデータ削除・プライベートウィンドウの終了・別端末や別ブラウザでの利用によって失われます。正式なバックアップは必ず「JSON書き出し」で取得してください。「JSON読み込み」でいつでも復元できます。

## 重要な前提

- **想定ブラウザ**: Microsoft Edge / Google Chrome などの Chromium系ブラウザです。PACへ渡されるURLがpath/queryを除去される挙動を前提にテストエンジンを実装しているため、Firefox では判定結果が実機と異なる場合があります。
- **実通信テストではありません**: 実際のWebサイトへの接続確認やプロキシ経由の通信テストは一切行いません。検証できるのは `FindProxyForURL()` の**論理的な判定結果**だけです。PACの記述が正しくても、経路そのものが疎通するかは別途確認してください。
- **名前解決は行いません**: DNS問い合わせを行わないため、IPアドレス条件は「URLのhost自体がIPアドレスである場合の完全一致」のみに一致します。ホスト名で書かれたURLは、そのホストが該当IPへ解決される場合でも一致しません。

## 初期サンプルデータについて

初回起動時には、機能を把握しやすいよう架空のサンプルシステム・アクセス経路・ガードテストが投入されています。実在のシステム名やIPアドレスは含まれておらず、IPアドレスは例示用として予約されたアドレス帯（192.0.2.0/24 等、RFC 5737）を使用しています。不要になった場合は「システム」タブに表示されるバナーから一括削除できます。

サンプルを編集して保存したデータは、ご自身のデータとして扱われるため一括削除の対象外になります。
